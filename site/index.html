JCL Grading

Free open-source exam grading for convention or classroom use: build the answer sheet, write the key, print and scan, grade, and fix unclear marks.

How this works

  1. Connect to the grading server. You only do this once per browser.
  2. Design and print the answer sheet.
  3. List the tests that go on it.
  4. Enter the answer keys. This can wait until after the exam if you would rather.
  5. Advanced settings, which most people can skip.
  6. Scan the completed sheets and upload them here.
  7. Fix anything unclear, and download the results.

Where data is stored: Your setup, answer keys, thresholds, and results are saved locally in this browser on this device. Uploaded scan PDFs are temporarily sent to the grading server for processing, then deleted; they are not retained on the server.

Printing

  • Print double-sided (your printer may call this duplex).
  • Use 100% scale if possible. "Fit to page" is acceptable if your printer requires it, but it makes the bubbles smaller.
  • Do not print two pages to a sheet.

C. Review answers (optional)

Every answer is editable here, however it got in. A cell you have typed into is shown in bold.

What goes in a cell

C The answer is C.
ABD The answer is A, B and D. The student must fill all three.
A|BD Either is accepted: A on its own, or B and D together.
X Exclude this question from scoring. Use if you discover after the test that a question should not count.
- You have not entered this answer yet (placeholder).

X means the question is finished and will not be scored, while - just means you have not typed it in yet.

Technical notes
  • Case does not matter. abd and ABD are the same answer, and so are x and X.
  • Order does not matter. BD and DB are the same answer.
  • More than two alternatives are fine. A|B|CD accepts A, or B, or C and D together. There is no limit on how many you list.
  • A repeated letter is an error. AA is rejected, as is a stray | such as A|, and any letter outside A–E.
  • A and B can be mixed. They write to the same answers, and the grid shows whatever is there.
  • Uploading merges, instead of replacing. A column whose Test ID matches a test you already have updates that test; anything else is added. Tests not mentioned in the file are left alone, and Undo upload puts everything back.
  • The file is Keys.csv. The field names run down the first column (Name, Test ID, Allowed, then 1 to 80) with one further column per test.
5 Advanced Defaults

Nothing here needs changing for an ordinary run. It is all remembered, and applies to every batch you grade from now on.

Which tests to grade

Every test on the sheet, unless you say otherwise. Untick one and its columns are not read at all: no results, no answer key needed, and nothing on the review sheets. Useful when a test is scored elsewhere, or when its key is not ready yet.

Marked-up scans

Marked-up scans show which bubbles were read as filled, along with the correct answer. They make a run noticeably slower, so leave this off unless you are demoing or debugging.

Thresholds

Every bubble is measured for darkness on a scale from 0 (blank paper) to 1 (solid black). A bubble darker than the cutoff counts as filled. One that lands between the review threshold and the cutoff is too close to call, so it is counted neither way and goes to step 7 for a person to decide. Anything fainter is ignored.

Where those two lines fall depends on the scanner, the paper and how hard the students pressed, so the server measures them from each batch of scans rather than using fixed numbers.

A higher number is stricter: it demands a darker mark. Leave a box empty to compute that one automatically — you can pin one number and let the other three be measured.

After a run, Calibration.txt shows the computed thresholds, so you can copy those numbers here to repeat it.

6 Scan and grade Nothing graded

At the scanner: required

  • Scan each sheet as two consecutive PDF pages: front first, back second. Do not scan all fronts first and all backs afterward. The run stops if the pages do not alternate, rather than grade the wrong back against the wrong front.
  • Turn off blank page removal. It will quietly drop a lightly-marked page and throw the whole batch out of order.
  • Do not crop into the four corner marks. The reader finds the grid from them, so a tight auto-crop can make a page unreadable.

At the scanner: recommended

  • 200–300 dpi. Color, grayscale or black and white all work; grayscale keeps the files small.
  • Deskew and auto-rotate can be left on or off. The reader straightens the page itself and corrects one that comes through sideways or upside down, so neither setting will break a batch.
  • Save one PDF per batch of about 25 sheets — your scanner can usually start a new file every 50 pages for you. This keeps each upload small enough for the server to handle; the hard limit is 40 MB. If a scan is too big, break it into smaller pieces and add each as its own batch.

Grading

A batch is one PDF from the scanner, holding whole sheets. Each is graded on its own and keeps its own results, so you can start grading the first stack while the rest is still being scanned.

If a mark was read wrong or the key was wrong, fix it in step 7: that re-scores from the results already here, without re-reading the scans. If the paper itself needs re-reading, scan it again and add it as a new batch — a batch that has been graded stays as it was.

7 Fix unclear marks Nothing to review

Two kinds of thing reach this step. Unclear is a bubble too faint to call — the reader neither counts it nor ignores it, and asks instead. Missing is a required field it could not read at all. A question left blank is not an error: that is the student's choice.

Each file asks for one correction per row. Open it, check the paper, fill in the answer, mark the row Done, and upload it below. Every row has to be marked Done — an untouched row means nobody has looked at it, and the upload is refused.

Google Sheets is optional

Any editor that saves CSV will do — Excel, Numbers, even a text editor. Nothing here needs Google Sheets.

Sheets is worth setting up when several people are correcting at once. Everyone opens the same file and works through different rows at the same time, and you download it once at the end. The script below is a convenience on top of that — it adds checkboxes so nobody has to type TRUE, restores the leading zeros on Student IDs that a spreadsheet would otherwise eat, fits the columns, and trims the blank rows.

  1. Create a Google Sheet shared with whoever is helping.
  2. Extensions → Apps Script, paste in Sheet.gs, and Save.
  3. Click the Triggers (clock) icon → Add Trigger.
    • function — onSpreadsheetChange
    • source — From spreadsheet
    • type — On change
    • Save and accept the prompt.
  4. For each file: File → Import → Insert new sheet(s). It has to create a new sheet — "Replace current sheet" will not trigger the script.
  5. When the sheet is finished, File → Download → Comma-separated values.
